# V10 生产部署

1. **本阶段目标**：将已完成的 Vue 和 Spring Boot 项目整理成可在 Linux 上运行的发布产物。
2. **上一阶段有什么**：V9 已有鉴权、测试、OpenAPI、监控与 CI，但运行入口仍面向本机开发。
3. **本阶段新增什么**：`application-prod.properties`、Nginx HTTPS 配置、systemd 服务、秘密环境文件模板、部署和架构文档。
4. **纵向请求链**：浏览器 HTTPS → Nginx → 静态 Vue 或 `/api`/`/ws` → 本机 8080 Java → MySQL/Redis/RabbitMQ。HTTP 80 先跳转 HTTPS。
5. **数据形态变化**：源码分别构建成前端 `dist/` 和后端 jar；实际密码只存在服务器环境文件，不进入 jar 或 Git。
6. **新增技术的位置**：Nginx 是公网入口，systemd 管理 Java 进程和日志，Actuator 从服务器本机提供健康状态。
7. **核心目录变化**：新增 `deploy/`、`docs/architecture/` 和后端 prod profile；README 补齐最终项目入口。
8. **API 变化**：业务 API 无变化。生产环境关闭 Swagger/OpenAPI 调试页面，Nginx 不转发 `/actuator/`；本机仍可查询健康检查。
9. **数据库变化**：本阶段无新表。部署已有库前先备份，只执行尚未执行的迁移。
10. **手工验证步骤**：构建 jar/dist；在目标 Linux 主机配置秘密、证书和依赖；用 `nginx -t`、`systemctl status minimall`、本机 `/actuator/health` 验证进程，再检查 HTTP 301、HTTPS 页面、登录、订单和 WebSocket。若没有服务器，先按部署手册静态检查配置。
11. **自动测试**：`mvn clean test && mvn clean package`、`npm ci && npm run build`；GitHub Actions 继续执行带数据库的后端测试和前端构建。
12. **常见错误**：Nginx 改写 `/api` 前缀导致 404；WebSocket 未转发 Upgrade；证书签发前就启用引用不存在证书的配置；将示例密码原样投入生产；把 8080 暴露公网。
13. **本阶段掌握判定**：能说明域名和证书、Nginx、前后端构建产物、systemd、环境变量及健康检查在部署中分别做什么。
14. **后续可扩展方向**：按需增加 Outbox、自动发布和真实服务监控；主线到 V10 完成。
15. **checkout 当前版本**：`git checkout v10`。部署步骤见 [部署架构](../architecture/deployment.md)。
