# V3 工程化 API 基础

1. **本阶段目标**：让 API 成功和失败都有可预测的契约。
2. **上一阶段有什么**：CRUD、分页与动态查询，但错误格式不一致。
3. **本阶段新增什么**：`Result<T>`、Bean Validation、业务异常、全局异常处理、SLF4J 日志与前端 API 层。
4. **纵向请求链**：HTTP → Controller 的 `@Valid` → Service → Mapper；异常 → `@RestControllerAdvice` → HTTP 状态码与 Result → Axios 拦截器。
5. **数据形态变化**：成功 `{code,message,data}`；失败 `{code,message,data:null}`，HTTP 状态与 code 一致。
6. **新增技术的位置**：Validation 在 Controller 入参；业务异常由 Service 抛出；Advice 在返回边界统一转换。
7. **核心目录变化**：后端 `common`、`exception`；前端 `api/http.js`、`api/product.js`、`views/ProductView.vue`。
8. **API 变化**：商品接口返回 Result；新增返回 201，不存在返回 404，非法参数返回 400。
9. **数据库变化**：无。
10. **手工验证步骤**：试空名称、负价格、负库存、非法 page/pageSize、错误 JSON、不存在的商品，并检查 HTTP 状态与 message。
11. **自动测试**：`mvn test && mvn package`；`npm ci && npm run build`。
12. **常见错误**：只改 JSON code 而忘记 HTTP 状态；前端重复解包；日志泄漏敏感信息。
13. **本阶段掌握判定**：能解释参数错误、业务错误、JSON 错误与系统错误分别在哪处理。
14. **下一阶段为什么存在**：商品操作仍是单表，V4 用订单组织多条 SQL 和事务。
15. **checkout 当前版本**：`git checkout v3`。
