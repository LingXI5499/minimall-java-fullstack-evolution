# V4 订单与事务

1. **本阶段目标**：让 Service 编排多表业务，并观察事务提交与回滚。
2. **上一阶段有什么**：单表商品 CRUD 和统一 API 契约。
3. **本阶段新增什么**：订单、明细、创建/列表/详情接口、库存扣减和 Vue Router。
4. **纵向请求链**：Vue `/orders` → `OrderCreateDTO` → Controller → `@Transactional` Service → Product/Order/OrderItem Mapper → MySQL。
5. **数据形态变化**：商品 ID 与数量 → 单价和小计 → 总金额 → `orders` 与 `order_item` 数据行 → `OrderDetailVO`。
6. **新增技术的位置**：事务代理围住 Service 的创建方法，多个 Mapper 使用同一数据库事务。
7. **核心目录变化**：新增订单 DTO、Entity、VO、Mapper XML、Service、Controller 和前端订单视图。
8. **API 变化**：`POST /api/orders`、`GET /api/orders`、`GET /api/orders/{id}`。
9. **数据库变化**：新增 `orders`、`order_item`；本阶段库存先按读后更新，V5 才改并发保护。
10. **手工验证步骤**：启动时加 `--app.demo.rollback-enabled=true`。先查询 `SELECT COUNT(*) FROM orders`、`order_item` 和目标库存；提交 `{ "items":[{"productId":1,"quantity":1}], "simulateFailure":true }` 应返回 500。再次查询两表计数和库存，应完全不变。正常提交同样请求但不带 `simulateFailure`，应新增订单与明细并扣减库存。
11. **自动测试**：`mvn test && mvn package`；`npm ci && npm run build`。
12. **常见错误**：在 Controller 上开事务但 Service 内自调用；提前返回 HTTP 成功；异常被吞掉导致提交。
13. **本阶段掌握判定**：能指出 `INSERT orders`、`INSERT order_item`、`UPDATE product` 任一步异常为何必须整体回滚。
14. **下一阶段为什么存在**：读库存再更新会在并发下超卖，V5 增加原子条件更新与数据关系。
15. **checkout 当前版本**：`git checkout v4`。
