# V8 WebSocket 与 Spring Task

1. **本阶段目标**：让浏览器实时看到订单变化，并让服务端按时间自动关闭超时订单。
2. **上一阶段有什么**：RabbitMQ 异步通知，但页面要主动刷新才能看订单变化。
3. **本阶段新增什么**：`/ws/orders` WebSocket、连接状态、创建/关闭通知、`@Scheduled` 超时扫描。
4. **纵向请求链**：订单提交 → AFTER_COMMIT → WebSocket → 浏览器 → 重新拉取订单。另一条链：Clock → `@Scheduled` → OrderExpiryService → MySQL → AFTER_COMMIT → WebSocket。
5. **数据形态变化**：服务端 `{type,orderId}` JSON 事件 → 页面通知；关闭订单更新 `orders.status` 并归还 product.stock。
6. **新增技术的位置**：WebSocket 握手是 HTTP 升级，后续为持久连接；定时任务由时钟触发，不经过 Controller。
7. **核心目录变化**：新增 `realtime`、`task`，前端订单页增加 WebSocket 连接和重连。
8. **API 变化**：新增 WebSocket `/ws/orders`；订单列表/详情仍走 HTTP API。
9. **数据库变化**：无新表；订单状态新增 `CLOSED`，在一个事务中恢复库存。
10. **手工验证步骤**：打开订单页，确认连接状态为“已连接”；创建订单，无需刷新应出现创建通知。将超时参数临时设为 2 秒、扫描间隔设为 1000 毫秒，观察自动关闭通知、详情状态为 CLOSED、库存恢复。
11. **自动测试**：`mvn test && mvn package`；`npm ci && npm run build`。
12. **常见错误**：事务未提交就推送；关闭订单却不归还库存；任务自调用绕过事务代理；多个任务实例重复处理同一订单。
13. **本阶段掌握判定**：能说明 WebSocket 连接的入口与 `@Scheduled` 的时间入口和 Controller 的 HTTP 入口有何不同。
14. **下一阶段为什么存在**：后台页面和管理接口目前没有身份权限保护，V9 加入认证授权与工程质量。
15. **checkout 当前版本**：`git checkout v8`。
