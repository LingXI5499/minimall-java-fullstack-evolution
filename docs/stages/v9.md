# V9 Security 与工程质量

1. **本阶段目标**：保护管理操作，并让测试、文档和监控成为可复现的工程能力。
2. **上一阶段有什么**：订单实时通知和定时关闭，但任何访问者都能调用管理接口。
3. **本阶段新增什么**：用户名密码登录、JWT、角色权限、订单 owner、WebSocket 一次性票据、AOP 日志、OpenAPI、Actuator 与 CI。
4. **纵向请求链**：HTTP → Security FilterChain → JWT 解码和角色授权 → DispatcherServlet → Controller → Service；WebSocket 先用 JWT 获取短期票据，握手时消费。
5. **数据形态变化**：登录凭据 → JWT（subject、role、过期时间）→ Authentication；订单头新增 owner_username。
6. **新增技术的位置**：Security 在 MVC 之前；AOP 环绕控制层成功操作；Actuator 暴露健康和指标；OpenAPI 描述接口契约。
7. **核心目录变化**：`security`、`audit`、`src/test/integration`、`.github/workflows/ci.yml`、前端登录和会话模块。
8. **API 变化**：`POST /api/auth/login`、`POST /api/auth/ws-ticket`；商品写入仅 ADMIN，USER 可读商品并创建/查看自己的订单，ADMIN 可查看全部订单。
9. **数据库变化**：V9 迁移增加 `orders.owner_username` 和索引；历史订单 owner 为空，只对 ADMIN 可见。
10. **手工验证步骤**：未登录读商品得 401；USER 读商品 200、写商品 403、只能查看自己的订单；ADMIN 可写商品并看全部订单。WebSocket 票据首次使用成功，重复使用失败；`/v3/api-docs` 返回文档，`/actuator/health` 返回依赖状态。
11. **自动测试**：`mvn test && mvn package`；配置 MySQL 后 `RUN_DB_TESTS=true mvn test` 跑 Service、Mapper、回滚、Controller 与安全测试；`npm ci && npm run build`；CI 在 MySQL 服务上执行同一套测试。
12. **常见错误**：只在前端隐藏按钮而不做后端授权；把 JWT 放进 WebSocket URL；把真实密钥写进源码；把健康检查 503 误报为服务进程没启动（也可能是依赖不可用）。
13. **本阶段掌握判定**：能解释 401 与 403、角色转换、订单 owner 校验、一次性握手票据，以及单元/集成/事务测试分别验证什么。
14. **下一阶段为什么存在**：目前仍依赖本机开发服务器，V10 完成 Linux、Nginx、HTTPS 和进程管理。
15. **checkout 当前版本**：`git checkout v9`。
